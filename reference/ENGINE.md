## core.js API (`window.C`)
| | |
|---|---|
| `C.W, C.H, C.FMT, C.FPS, C.DUR` | frame size from `?fmt=`; `C.pick(wide, square, tall)` returns a per-format value |
| `C.VARIANT` | styleframe variant: `?variant=` from `render.mjs --frames`, otherwise the pick in `timeline.json` `"variant"`, otherwise `'a'` |
| `C.ui(parent, id, {x, y, scale})` | live component from `assets/ui/` (in `build()` only): `{root, w, h, q(text), all(sel), fields}`. See "Live components" below |
| `C.bt(beatOrMark)` / `C.beatAt(t)` / `C.beatOf(mark)` | beat ↔ seconds on the measured grid; `beatOf` — mark → beat |
| `C.sp(t, beat, preset)` | 0→1 spring released on a beat (motion with no sound) |
| `C.spHit(t, beat, preset)` | same, but led so it READS on the beat (anything with an SFX or VO hit) |
| `C.trk(t, [[beat, v, preset?], …])` / `C.trkObj` | value with several targets. Retargets keep velocity |
| `C.win(t, b0, b1)` | 1 inside [b0, b1) with spring edges |
| `C.seg(t, b0, b1)` + `C.ease.*` | linear progress. Only for typing, scrolls, slow pushes, push-throughs |
| `Motion.indicator(t, stops)` | bar/underline between stops: the leading edge is stiffer, so it stretches and settles |
| `Motion.swapAlpha(t, tIn, tOut)` | text inside a morphing box. Invisible while the box changes shape |
| `C.el(tag, attrs, parent, html)` `C.frag(html)` | build DOM (in `build()` only) |
| `C.reg(el, base)` | register an animated element. Hidden things: `{o: 0}` |
| `C.anchor(el, target, where, {gap, inset})` | place a label, chip, badge or stamp **by its object**, not by box coordinates (`build()` only, shared parent): `'below'`/`'above'` centred on the object, `'left'`/`'right'`, corners `'tl' 'tr' 'bl' 'br'` (element centre on the corner, `inset` inwards), `'center'`. Centring holds whatever the element's final width. `put()` still animates the element itself |
| `C.put(el, {x, y, s, sx, sy, r, o, hide, clip, filter, css, text, html})` | this frame's props; unset props return to base |
| `C.inset(t, r, b, l, radius)` | clip-path for wipes/reveals |
| `C.rectOf(el)` | live stage rect. Only in `after()` |
| `C.canvas(parent)` | full-frame 2D context (clear it in `run()` every frame) |
| `C.hooks.before/after.push(fn)` | global per-frame work: camera, cursor, overlays |
| `C.mulberry32(seed)`, `C.noise1(seed)` | seeded randomness |
| `C.fonts = ['600 100px Display', …]` | awaited before frame 0. A missing face logs `[page] font failed` |
| `C.gates.push(promise)` | in `build()`: frame 0 waits for it too (a Lottie file loading, a file decoding) |

## Scenes
```js
scene({
  name: 'features', from: 'mid', to: 'end',   // beats or marks; root visible on [from - pre, to + post)
  pre: 0, post: 0,                              // overlap for whips/wipes. cut defaults to pre === 0
  build(root, S) { /* DOM once; store on S */ },
  run(t, b, S)   { /* put() everything you animate, every frame */ },
  after(t, b, S) { /* things that follow live layout (rectOf) */ },
});
C.start();   // last line of film.js
```
`window.CUTS` is derived from scenes with `cut`. Motion-blur sub-frames never straddle a cut.

`window.seek(sampleTime, frameTime = sampleTime)` distinguishes shutter-sample time from output-frame time. Inside
`run`/hooks, `C.frameTime` selects discrete caption pages, counter strings or typed characters. Compute continuous
geometry/transitions from `t`. Otherwise a shutter may average two different phrases into double exposure. Ordinary
`seek(t)` resets frameTime to t, so a previous render does not leak into preview. `CAPTIONS.karaoke` holds its page
automatically; with `exit:'cut'`, the next page does not pre-roll over the previous one. To upgrade an existing project,
copy `core.js`, `lib/captions.js` and `scripts/render.mjs` together.

## Captions (`lib/captions.js`, `window.CAPTIONS`)
`captions.json` is a list of `[mark, "text"]` entries (`captions.py` drafts it, then you edit it by hand); `"|"` inside an
entry splits it into parts shown one after another. An optional third element: `{"key": ["word"]}`.
Call one of the two in `film.js` before `C.start()`:

```js
CAPTIONS.scene({ x, y, w, size });   // plain caption: the whole line rises into its slot on the speech chunk <id>.<k>
CAPTIONS.karaoke({ x, w, size, bottom, y, align, dim, key, keys, accent, color, bg, font, weight, keyCss, frames, rise, blur, enterMin, exit,
                   current, ahead, plate, plateInk });
```
`enterMin` (0–1) — a floor on an entering word's opacity: on a coloured plate the word has contrast from its first frame, and lint does not flag half-transparent text.

**Karaoke** (the "image per phrase" format, FORMATS.md) shows the phrase word by word, exactly with the voice:
- a word enters on its own mark `<id>.w<k>` (AUDIO.md): over `frames` frames (4) it rises `rise` px (8) and sharpens from
  `blur` px (6) to zero. The entry starts one frame before the mark, so the word is already visible on the mark's frame;
- `exit: 'cut'` drops the phrase on its last frame instead of the 4-frame blur-out: use it in a film with no dissolves;
- words already said drop to `dim` (0.55), the current one stays at full strength. If the dimmed text reads below 4.5:1
  on the background, `dim` is raised until it reads at 4.5:1;
- key words (the entry's `"key"` and the film-wide `keys`; a multi-word key is `"new paragraph"`) take the preset's
  accent. `key: 'auto'` (default): the `--accent` colour when it reads at ≥ 4.5:1 on the background, otherwise an
  accent plate under dark or light text (whichever contrasts more, also ≥ 4.5:1); `'color'` and `'chip'` force one.
  An accent face goes through `keyCss` (e.g. `font-style:italic;font-family:Display`);
- the next entry, or the next part after `"|"`, resets the whole phrase: it leaves within 4 frames before the next one's
  first word. The last entry before a pause holds until the phrase ends + 0.6 beat;
- line breaks are laid out for the whole part at once: words never shift as their neighbours enter;
- default placement is at the bottom: last line above the edge by `bottom` (84 / 90 / 20% height + 40 px for 16:9 / 1:1 / 9:16).
  Explicit `y` sets the top of the box; a top caption is recorded per STYLES "Where it is recorded". `align: 'left'`,
  size 64 / 60 / 68 px for 16:9 / 1:1 / 9:16;
- `sync.mjs` matches an entry's words to marks (→ `window.CAPW`): in order, against the line's words. A word spelled
  differently on screen ("1 200" for "twelve hundred") takes the mark of the line's next word, and sync prints a WARN
  listing them. A line without word marks (an older project, an overlay without word timings) shares the entry's time by
  letter count, with a warning in the page console;
- `current: true` is an option, not the default: the whole page is on screen from its first word, words not yet said at
  `ahead` opacity (0.42), the spoken word on a `plate` (default `var(--ink)`) in `plateInk` (`var(--bg)`). It reads like a
  teleprompter: for a dark stage with an object, or a talking head where the page must be taken in at a glance. Tested
  2026-10-28 on a rebuild of someone else's reel (9:16, `--verify` 12/12);
- a pure function of time: no timers, no Math.random; `render.mjs --verify` checks it. Word marks work anywhere in the
  film, not only in captions: a prop changes state with a spring on `<id>.w<k>`.

Check: `render.mjs --at s2a.w3-0.0334,s2a.w3,s2a.w3+0.05 --fmt 9x16` — two frames before the mark the word is not there,
on the mark's frame it enters, 3 frames later it stands.

## Patterns that fixed real problems
- **Hook on frame 0:** release word 0 at a negative beat (`[-0.4, …]`) so frame 0 already reads.
- **Sync:** visuals read ~100 ms late when a masked word starts on the beat. `spHit` leads by max(3 frames, half the spring's travel).
- **Swaps:** set `outAt` from the next line's in-beat. Exit ≈ 0.14 s. No double exposure at swaps.
- **Handoffs:** start the incoming scene under full cover (a wipe or whip) so there are no blank frames mid-whip.
- **9:16:** re-block per format with `pick()`. Don't letterbox 16:9. Move things apart vertically and use bigger crops of the real UI.
- **Loop:** see the "Loop" section below.
- **Camera multipliers compound.** If one scene multiplies zoom, divide it out downstream.
- **Depth:** perspective on UI cards enters at a steeper angle and settles at 4–10° (RULES "Light and depth"), plus deep soft contact shadows. Never glow. CSS 3D creates composited layers: run `render.mjs --verify`, and fall back to 2D skew + scale if it fails.

## Live components (`capture.mjs --components`, `C.ui`)
A screen whose state changes in a scene is neither swapped for a second screenshot nor redrawn by eye: the block itself is
carried over from the site.
```
node scripts/capture.mjs https://product.example --components "New task,css:.composer"   # text inside the block, or css:selector
node scripts/sync.mjs                                                                    # assets/ui/*.json → window.UI in data.js
```
- The block is the smallest ancestor holding that text that is at least `--min-width` (240 px) wide. Every element gets its
  computed styles (inherited ones only where they differ from the parent; on form fields always), `::before`/`::after`, images go to
  `assets/ui/img/`, fonts become `@font-face` rules on the files in `assets/fonts/` (including CSS served from a CDN). Classes and ids
  are dropped, except ids inside SVG.
- A text field becomes a box with two spans, `data-value` and `data-placeholder`; type into them with a plain `put(…, {text})`.
- **The check.** `<id>.ref.png` is the block on the site with everything around it hidden; `<id>.check.png` is the carried-over copy
  on its own, on the same background. Over `--max-diff` (3 %) of pixels off, or a size off by more than 2 px, is `pixel check FAILED`,
  and `sync.mjs` warns. Do not use such a component. `<id>.png` is the block in place on the page: what was behind it.
- WARN `blends with what is behind it`: part of the block blends with its backdrop (`mix-blend-mode`, `backdrop-filter`); put the
  site's backdrop behind it. `canvas`, `video` and `iframe` are not carried over — show that part as a screenshot.
- States that are not on the page at capture time (hover, an open menu, a second screen) are not carried over: build them from the
  component with `put(…, {css, text})`, or capture them in a separate run from a page where they are visible.
```js
build(root, S) {
  S.U = C.ui(root, 'composer', { x: 140, y: C.pick(300, 300, 640), scale: 1.6 });   // registered: put(S.U.root, {y, s, o})
  S.f = S.U.fields[0]; reg(S.f.value); reg(S.f.placeholder);
  S.send = reg(S.U.q('Send'));                                                        // innermost element with this text
},
run(t, b, S) {
  const n = TYPE.type(t, S.f.value, 'Draft the Friday report', 's3.1', 's3.2');
  put(S.f.placeholder, { o: n ? 0 : 1 });
  put(S.send, { css: { background: C.win(t, 's3.2', 's3.3') > 0.5 ? 'var(--accent)' : '' } });
},
```

## Render speed (motion-film)
Video modes (`--draft`, finals, `--range`) run in parallel: the range is cut into `--chunk` seconds (default 4) and
`--workers` processes (default: CPU cores − 4, max 4), each with its own Chromium, encode chunks that are joined
losslessly. Measured on an Apple M1 (8 cores), 2:36 film, 1920×1080, 60 fps with motion blur: **9 min 46 s instead of
~42 min**. Two changes do it:
- `png.mjs` decodes Chromium's screenshots with typed-array fast paths: 4–10 ms instead of ~40 ms per frame,
  bit-exact (the single-process output is byte-identical to the original renderer);
- parallel chunks: ×2.4 on top. More than 4 workers is slower on an M1 (4 performance cores).
Parallel and serial output differ only where Chromium's raster cache depends on which frame it painted before (edge
antialiasing of a moving card): worst frame 71 dB PSNR against a serial render, sharpness equal. `--workers 1` gives
the serial path. GPU flags (`--use-angle=metal`) make screenshots 5× slower: do not add them.

## Picture finish (motion-film)
Finals and `--range` send frames to ffmpeg in 16 bits (`rgb48le`): the motion-blur average keeps its fractions. In 16 bits the
frame goes through `deband` (on by default) and an optional `.cube` LUT, and drops to 8 bits only at the last step, with
error diffusion (`sws_dither=ed`). Drafts stay 8-bit.
`timeline.json`: `"finish": {"deband": true, "lut": "assets/brand/grade.cube", "grain": 0, "master": false}`; the flags
`--deband [thr]`, `--lut`, `--grain N`, `--master`, `--no-finish` override it.
- **Grain** (`grain`, 1.5–2.5 steps of the 8-bit scale) is monochrome, midtones only, and computed from the absolute frame
  number, so a parallel render matches a serial one byte for byte (verified with `--crf 0`). Grain is a look, not a cure for
  banding: deband and dithering are.
- **`--master`** also writes `renders/<fmt>_master.mp4`: HEVC 10-bit, `hvc1`, from the same frames (~35 % more time).
  The main `<fmt>.mp4` stays H.264 8-bit for chats and players.
- Colour: both files are tagged bt709/bt709/bt709, tv range. Check: `ffprobe -show_entries stream=color_primaries,color_transfer,color_space`.
- Cost (M1, 4 s of film): 16-bit + deband + dither — same time, file +20 %; with `--master` and grain, +35 % time.

## Motion roles (motion tokens)
One film, one motion language. Roles are preset names too and work wherever a preset does: `C.sp(t, b, 'enter')`,
`C.spHit`, `C.trk`, `TYPE.rise` (default `text`), `CAM.rig` (default `camera`).

| role | default | for |
|---|---|---|
| `enter` / `ui` | `default` | cards and UI coming in |
| `exit` | `snappy` | leaving |
| `text` | `heavy` | big type |
| `accent` | `snappy` | pills, underlines, clicks |
| `hero` | `heavy` | the hero moment |
| `camera` | `heavy` with a soft start (`soft: 0.12`) | the camera |

A brand retunes them in one place, `timeline.json`:
`"motion": {"roles": {"enter": "snappy"}, "presets": {"default": {"response": 0.35, "damping": 0.9}}, "stagger": 0.05}`.
**Soft start (`soft`, s).** A spring released at rest gets its full acceleration on the first frame; on a slow camera that
reads as a jolt (measured 2026-10-11: peak acceleration 150 vs ~3 with `soft`). `soft` averages the response over a window
of that length, in closed form: acceleration ramps up, the motion lags by about `soft/2`. Default only for the `camera` role;
for your own preset — `"presets": {"dolly": {"response": 1.1, "damping": 1, "soft": 0.12}}`. Hits on a beat do not need it.
`C.stagger(i)` is the i-th cascade delay in seconds (0.05 by default: cascade 30–80 ms, ≤ 8 a wave).

## WebGL layer: three.js + post-processing (motion-film)
For what the DOM cannot do: a 3D hero, physical materials and light, glass, depth of field, bloom, a device with a real
screenshot on its screen. `engine/lib/gl.js` (three.js MIT, postprocessing Zlib — installed in the shared toolchain).
1. `timeline.json`: `"webgl": true`. The render switches to the GPU (ANGLE Metal) by itself: a post-processed frame takes
   ~95 ms there against ~1.4 s on the software rasteriser. By hand: `--gpu`.
2. In `film/index.html`, after `film.js`: an import map (`three`, `three/addons/`, `postprocessing` → `/node_modules/…`, sample in
   the header of `gl.js`) and `<script type="module" src="gl.js"></script>`.
3. `film/gl.js`: `const L = await layer(sceneRoot, { dof, bloom, vignette, tone, env, bg })` — a transparent layer over the scene's DOM;
   `L.scene.add(...)`, `L.frame((t, b) => …)` sets every value from t (springs `C.sp`, `C.seg` work as in the DOM);
   `L.texture('assets/shots/x.png')` — a real screenshot as a texture, `L.gltf('assets/3d/x.glb')` — a model,
   `env: 'assets/3d/x.hdr'` — an HDRI (Poly Haven, CC0). End with `C.glDone()`: frame 0 waits for it.
- `tone` defaults to `neutral` — for lit 3D: soft highlights, and the brand colour holds better than in AgX and ACES. For flat
  2D (particles, shader transitions, exact brand colours) use `tone: 'none'`: `neutral` turns white into 240/255 and dulls the
  accent's blue channel (measured 2026-10-11). Grain is not here but in `finish.grain`.
- Glow: `bloom` is additive, for a dark ground; on a light one it washes the frame out. On a light ground use `glow: { strength,
  size, color }`: a halo of the layer's own blurred content goes UNDER it and leaves the ground alone. `color` (usually the
  accent) tints the halo by coverage: blurred dark dots otherwise make a grey haze. Give the layer its ground with `bg`, not a
  full-frame plane: the halo goes between them.
- Depth of field `dof: { focus, target, range, bokeh }` is in the scene's world units: `focus` is the distance from the camera,
  `target` a `THREE.Vector3` kept sharp while the camera moves; with neither it autofocuses on the origin. A focus pull:
  `L.dof.cocMaterial.focusDistance = d` in `L.frame`.
- The layer sits under the scene's DOM children by default (`z: 0`); to draw over them use `z: 10`.
- Verified (M1, 2026-10-06): `--verify` 12/12, frame t is the same in any order. A parallel render differs from a serial one
  by ±1 level in scattered pixels (worst frame 89 dB PSNR) — less than the DOM does (71 dB).
- Never: TAA and temporal effects, accumulation between frames, `clock.getDelta()`, unseeded `Math.random`, your own `requestAnimationFrame`.
  Metal and the software rasteriser give different pixels: one backend per film (`webgl` in the timeline guarantees it).
- Heavy: every motion-blur sub-frame renders the scene again. Keep the scene simple on fast 3D moves.
- Living background: `meshBackground(sceneRoot, ['#f6f5f1', '#fbe0d2', '#ffffff', '#f4c3ab'], { speed, radius, seed })` — a soft
  gradient under the scene's DOM that drifts slowly with t. The first colour is the ground, the rest are soft lights over it. Keep the
  palette tonal: one accent plus neutrals; a blue-to-purple wash reads as stock. Works without `layer()`, but needs `"webgl": true`.

## GSAP (kinetic type)
GSAP 3 is in the shared toolchain, including SplitText, DrawSVG, MorphSVG ("no charge" licence, commercial use allowed).
Only `seek(t)` drives time:
```js
gsap.ticker.lagSmoothing(0); gsap.ticker.remove(gsap.updateRoot); gsap.registerPlugin(SplitText);
gsap.config({ force3D: false });   // otherwise translate3d mid-tween: a composited layer, pixels depend on frame order
const tl = gsap.timeline({ paused: true });
tl.from(new SplitText(el, { type: 'chars', mask: 'words' }).chars, { yPercent: 120, stagger: 0.03, duration: 0.7, ease: 'expo.out' }, C.bt('s2a'));
tl.totalTime(tl.duration(), true).totalTime(0, true);   // prime: every tween initialised once
C.hooks.before.push((t) => tl.totalTime(t, true));
```
`force3D: false` and priming are required (measured 2026-10-11): without them 184 frames of 360 depended on which frame was rendered before —
`translate3d`, and MorphSVG drawing the start shape differently after a backward seek. Build the whole timeline before
priming; morph only with MorphSVG (anime.js collapses the shape when the start points do not match).
Load it with `<script src="/node_modules/gsap/dist/gsap.min.js">` (and the plugins) before `film.js`. GSAP animates only elements
not registered with `C.reg`: otherwise `C.put` and GSAP write the same `transform`.

## Ready-made Lottie (`lib/lottie.js`, `scripts/lottie.py`)
A designer's After Effects animation is media, like a real screenshot — not a way to animate. Use it when the brand or the
client has Lottie files, or for character motion (deformation, secondary motion) that looks wooden with springs. Icons and UI
are still built with springs: a Lottie file bakes in time and colour, so one phase cannot move onto a voice hit. Check the
file's licence; LottieFiles does not hand out files without a login.
1. `python3 scripts/lottie.py colors x.json` — comp size, frames, every colour (fills, strokes, gradients, keyframes).
2. `python3 scripts/lottie.py recolor x.json assets/lottie/x.json --map '#e31c5f=#2d5bff' …` — to the film's tokens; prints
   `NOT MAPPED` for every colour left, gradient stops included, and exits non-zero while any are.
3. `film/index.html` after `core.js`: `<script src="/node_modules/lottie-web/build/player/lottie_svg.min.js"></script>` and
   `<script src="lib/lottie.js"></script>`.
4. In a scene: `S.ok = LOTTIE.play(root, 'assets/lottie/x.json', { x, y, w, h, crop: [cx, cy, cw, ch], from: 's3a.2', hold: 78 })`
   in `build`, `S.ok.at(t)` in `run`. `crop` is the part of the comp that fills the box (the subject is often small in a large
   comp); `hold` the last frame shown (before a built-in fade-out); `loop` for loops.
SVG renderer only: under a 2× zoom it stays vector, canvas blurs (sharpness 73 vs 32). The final takes ~20 % longer: the
Lottie DOM is rebuilt on every motion-blur sub-frame. Verified 2026-10-11: `--verify` 12/12.

## Cutouts and depth for photos (`scripts/vision.py`, `depthPhoto`)
Photos of people, products, places only — on the hero or a "human" moment, one or two scenes per film.
A UI screenshot, text, a logo, a chart — never: a cutout gives a halo, parallax tears straight edges. Depth shift
≤ 3 % of the frame, otherwise tears show at object edges. Local models, downloaded once (~165 MB):
- `.venv/bin/python scripts/vision.py cutout assets/shots/x.jpg` → `x.cut.png` (transparent background): an `<img>` over its own
  background, the shadow a CSS `filter: drop-shadow(...)`. ~15 s a frame.
- `.venv/bin/python scripts/vision.py depth assets/shots/x.jpg` → `x.depth.png` (white = near). ~6 s.
- In `film/gl.js`: `await depthPhoto(sceneRoot, 'assets/shots/x.jpg', 'assets/shots/x.depth.png', { box, move: (t) => ({ x, y, z }) })` —
  `z` 0 to 1 = push-in, `x`/`y` = drift; `amount` 0.02 (≤ 0.03), `focus` 0.5 = the depth that stays put. Needs `"webgl": true`.

## A screen in 3D (`uiShot`, `lib/gl.js`)
Off by default: one or two scenes per film, only where the screen is the scene's point, with a `uiShot` note in the
shotlist and one sentence on why. Use it when: (a) the first look at the product — the viewer should feel "there it is, the
real thing"; (b) the voice names one detail of a big screen and the camera's path to it is the proof; (c) moving the focus
from one part of the screen to another is itself the comparison. Do not use it when: the screen has to be read whole (a
table, a list, numbers) — then a flat screenshot and `CAM.rig`; the screenshot is small or soft; the same shot was already
in the neighbouring scene. In frame: the detail the voice names is in focus and ≥ 40 px high, blur ≤ 8–10 px, the page
stands still — the camera travels along one rail, the angle 20–35° and no spin. 9:16 gets its own keys through `C.pick`.
A real screenshot is a plane in 3D, an oblique camera travels
along it, depth of field is a per-pixel thin lens. The background is transparent: the scene's preset ground shows through.
Needs `"webgl": true` (wired like the WebGL layer above).
```js
// film/gl.js
import { uiShot } from './lib/gl.js';
await uiShot(document.querySelector('[data-scene="product"]'), [{ id: 'page', src: 'assets/shots/app.png', w: 1870 }], {
  keys: [['s3',   { x: 260, y: 150, d: 760, yaw: -30, pitch: 14 }],   // look at point (x, y) of the screenshot from d px
         ['s3.2', { x: 1100, y: 330 }],                                // rail: only the target moves — the camera travels
         ['s3.4', { focus: 1100 }]],                                   // focus pull to the far side
  dof: { strength: 60, max: 10 } });
C.glDone();
```
- `keys` — `[[mark, {x, y, d, yaw, pitch, roll, focus}], …]`: a point on the screenshot (its pixels), distance, angles in
  degrees (`yaw` < 0 — the left edge is near). A key says only what changes. Springs of the `camera` role keep velocity; each
  key starts `lead` (0.4 s) before its mark, like `CAM.rig`. A hand-made path: `cam: (t, b) => ({...})` instead of `keys`.
- `persp` 1200: at `d` = `persp` and zero angles the screenshot shows 1:1.
- Depth of field: blur = min(`max`, `strength` · |1 − s / d|), s = focus distance (default `d`: the target is sharp),
  d = the pixel's depth along the camera axis. `strength` 40 — gentle, 80 — shallow. `dof: null` — all sharp.
- A second plane (a card above the page): `{ id, src, w, x, y, z, yaw, pitch, move: (t, b) => ({ z, o }) }` — a whole card
  only, never a cut-out piece ("Cutouts and depth for photos" above). Corner `radius` 24, `shadow` (on by default).
- Use the screenshot at full resolution: in a close shot one screenshot pixel must not grow beyond one frame pixel.
- Tested (M1, 2026-10-10): `--verify` 12/12 in 16:9 and 9:16, screenshot colour 1:1; a 6 s clip at 60 fps with motion blur —
  ~40 s on two workers.

## Video bridges (`scripts/broll.py`, `lib/footage.js`)
Only when the customer asks. 4–8 s of atmosphere between scenes: fog, light, material, space. No screens, text, faces or
logos — the model makes them up. One or two per film; name the price before `--yes`. In `timeline.json`:
`"broll": [{"id": "b1", "at": "s3", "seconds": 4, "prompt": "…", "model": "google/veo-3.1-fast", "resolution": "1080p"}]` —
the bridge plays from mark `at` (a mark name only) for `seconds` over the scenes; its first frame is the film's frame at `at`,
its last the film's frame at `at` + `seconds`, so scene B starts right there. `broll.py` with no flags prints the plan and the
price, `--yes` generates what is missing through OpenRouter (`assets/broll/<id>_<fmt>/`), then `node scripts/sync.mjs`. The engine
plays the frames itself: `seek(t)` waits for the frame to load (`C.pending`). Price at 1080p without audio: Veo 3.1 Fast
~$0.10/s, Lite ~$0.05/s (720p $0.03/s). `render.mjs --at` takes a mark with an offset: `s3+4`.

## Overlay on a recording (`scripts/overlay_prep.py`, `lib/footage.js`)
A finished recording (a talking head, a talk, an interview) is the bottom layer of the whole film, the engine's graphics are
drawn over it, the recording's own sound is the voice, and the marks come from its transcript (the transcriber skill:
`segments.json` with `raw.json` next to it for word timings; `.srt`/`.vtt` work too). This mode replaces step 4
(`extract_lines` → `voice.py` → `layout_vo.py` → `vo.py`):
```
python3 <skill>/scripts/overlay_prep.py talk.mp4 --transcript asr/segments.json [--scenes 36,120] [--min-scene 5] [--tail 2.5]
```
- Writes `assets/recording/<name>/00001.jpg…` (every source frame, up to 1080 px high by default, ~100 KB a frame: 4 minutes
  at 30 fps is about 0.7 GB), `audio/vo.wav` (the recording's sound, 48 kHz mono, aligned to the first video frame),
  `audio/vo/lines.json`, `audio/vo_placed.json` and marks in `timeline.json` named as `layout_vo.py` names them: `sc<N>`, a scene
  per transcript segment (short ones merged up to `--min-scene` s), `s<N><letter>`, a phrase per sentence, `<id>.<k>`, speech
  chunks split at word gaps of 0.12 s or more and at commas, `<id>.end`, `done`. Everything after it works as usual:
  `captions.py`, `sync.mjs`, `C.beatOf`, `plan_check.py`, `mix.py` (music under the voice, with the pocket). Do not run
  `layout_vo.py` or `vo.py` in this mode: they would rebuild `audio/vo.wav` from synthesised takes (`vo.py` refuses by
  itself: `vo.json` says `"provider": "recording"`).
- Word marks `<id>.w<k>` and `vo.json` with each phrase's display words, as `layout_vo.py` writes them, so karaoke and
  state changes on a word work over a recording too. A word the transcript spells differently gets its time from its
  neighbours by letter count. Before 2026-10-28 the script read word timings but wrote no word marks, and karaoke over a
  recording ran by letter count.
- `--cut-pauses S` is an option for a talking head that hesitates: every pause longer than S s is shortened to
  `--keep-pause` (0.3 s). Picture and sound are cut together on the source's frame grid into
  `assets/recording/<name>-cut.mp4`, which becomes the layer; transcript times and `--scenes` (in the original's seconds)
  move with it. Pauses come from word timings, without them from `silencedetect` (−35 dB). A jump cut in a face shows:
  cover it with graphics, a punch-in or a scene change — the cut points are in `timeline.json` → `recording.cut.at` (film
  seconds). Tested 2026-10-28: a 75.6 s recording, `--cut-pauses 0.25 --keep-pause 0.12` → 5 cuts, −1.2 s, picture and
  sound equal in length to the frame.
- Without word timings, phrases are split by letter count inside a segment and chunks by pauses in the sound; the script prints
  `ESTIMATED`.
- Sound and picture: the offset of the audio stream against the first video frame (`start_time` in ffprobe) is compensated,
  and the transcript times move by the same amount (an ASR counts from the first sample of the sound). `--shift` adds more.
- `timeline.json` gets `"mix": {"voice_chain": false, "room": 0}` unless already set (a recording keeps its own room and tone),
  and `fps` becomes the largest multiple of the source rate up to 60 (25 → 50, 30 → 60, 24 → 48), so every source frame stays on
  screen equally long (`--keep-fps` leaves it). `--tail` adds an end card over the frozen last frame, with silence.
- The layer (`footage.js`): source frame k is shown on [k/fps, (k+1)/fps), computed from t with nothing accumulated, so there is
  no drift. At another film rate frames repeat (25 in 60: 2 or 3 times) and never blend. The frame number is taken at the output
  frame time (`window.FRAME_T`, set by `render.mjs`), not at the motion-blur sub-frame time: two recording frames inside one
  output frame would ghost. Scenes are drawn over the recording: keep scene roots transparent, give them no background.
- Layout per format in `timeline.json`: `"recording": {…, "layout": {"9x16": {"mode": "split", "share": 0.45, "focus": [0.5, 0.4]}}}`.
  `cover`: the whole frame, cropped around `focus` (fractions of the source); `split`: the recording at the bottom, full width,
  `share` of the frame height, the graphics above it; `box`: `{x, y, w, h, radius}` in frame px (picture in picture). The default
  is `cover` when the aspect ratios match within 10 %, otherwise `split`. In `film.js`, `C.REC = {x, y, w, h, mode, box, img}` is
  the recording's rectangle for the layout (with `split`, graphics go above `C.REC.y`); `put(C.REC.img, { s })` punches in,
  `put(C.REC.box, { o })` hides it.
- Tested 2026-10-14 (a 25 fps test recording with a binary frame counter, `--draft --all` at 30 fps, `--range` at 50 and 60 fps
  with motion blur, `--at` on marks, 16:9 and 9:16 `split`): the source frame number matched floor(t * 25) in all 1350 draft
  frames, 440 clip frames and 10 stills, with 0 blended frames; without `FRAME_T`, 20 of 240 frames at 60 fps were blended.
  Sound: the source clicks land on the same millisecond in `audio/vo.wav` and 6 ms later in the mix; shifted streams (audio
  +0.2 s, video +0.2 s) come out aligned. `--verify` 12/12 in both formats.

## Loop (`Motion.loopT`, 2026-10-22)
A piece for a feed, a README, Telegram or X: 4–14 s, no voice, it plays on repeat. Same engine, same render; there is no
voice, no script and no argument chain, so there is no blind read either. **Route:**
1. **Brief** in one line: what loops, where it is shown (GIF, MP4), cycle length, frame format. The visual language comes
   from `FORMATS.md`, most often "One take".
2. **One stop instead of steps 2 and 5.** One message: the idea of the loop in one sentence, 3–6 states with their
   durations, the cycle length and the styleframe board (`render.mjs --frames`), the first frame being frame 0. Wait for
   OK. `SCRIPT.md`, `script_lint.py` and step 4 are not needed.
3. **A timeline without a voice.** `init.sh`, then in `timeline.json`: `"loop": true` (turns on the loop checks in
   `review.py` and `share.py`), `"voiceover": null`, `duration` = the cycle length, a `bpm` that fits a whole number of
   bars into the cycle. No sound by default; do not run `mix.py` (without `audio/mix.wav` the render writes no audio
   track). Sound only if it was asked for in the MP4; then steps 6 and 8 as usual.
4. **Build** — step 7 under the rules below.
5. **Check:** `render.mjs --draft --all`, `review.py 1 --draft`, `--lint --all`, `loop_seam.jpg` by eye. Without a voice
   `review.py` passes: the sound checks are NOT CHECKED and a calm loop gets a WARN `slides`; `--lint` with no text is
   NOT CHECKED. Critic — without the voice and caption items and without Sound sync if there is no sound. One round if
   every score is ≥ 8, otherwise another.
6. **Final:** `render.mjs --all`, then `share.py --gif [--gif-fps 15] [--mb N]` and/or `share.py` for an MP4. An MP4 for
   Telegram has no audio track (`ffprobe -select_streams a` is empty).

A cycle of length D at fps is N = D · fps frames (a whole number: D = 6 at 60 fps
gives 360). The seam is invisible only if frame N equals frame 0.
- **Phase = frame / N.** `const u = Motion.loopT(t, D, C.FPS), p = u / D;` — everything periodic is computed from p, not
  from t: `Math.sin(2 * Math.PI * k * p)` with an integer k. A rotation makes a whole number of turns per cycle, a drift a
  whole number of periods, a counter or progress bar returns to its frame-0 value by the end of the cycle.
- **Springs return to frame 0 before the seam.** The last state change brings the element back to where it stood on
  frame 0 and has time to settle: the return mark + `Motion.settle(preset)` ≤ D. A spring tail cut by the seam is a jump.
- **Noise on a circle.** For noise to come back to where it started, sample it on a circle, not along the time line: in a
  shader `noise(c + R · vec2(cos(2π p), sin(2π p)))`, in JS a sum of 3–4 harmonics `a_k · sin(2π k p + φ_k)` with
  integer k and phases from `C.mulberry32(seed)` (the same noise on a circle written as a Fourier series; it closes
  exactly). `C.noise1(seed)(t)`, `CAM.shake` and `meshBackground` run along straight t and do not close: keep them out of
  a loop.
- **Frames 0..N−1, no duplicate at the seam.** `render.mjs` already writes them that way (frame i is time i/fps, i < N), and
  `loopT` maps t = D to 0. Do not add a last frame equal to the first: the GIF shows it twice and the seam stutters.
- **Frame 0 is a finished composition.** It is visible while the GIF loads and it is the feed preview. Everything is in
  place and reads without motion, nothing is halfway. Also, the motion-blur sub-frames of frame 0 do not cross the seam
  (the render clips them at t = 0), so at the seam everything is at rest or moving slowly.
- **Check:** `timeline.json` → `"loop": true`; then `review.py` gives FAIL `loop` if there are not exactly D · fps frames or
  the step at the seam (`loop_seam`: luma, 480 px, mean |Δ|) falls outside 0.75–1.5 of the smaller step on either side.
  Luma only: in the final, frame 0 is the codec's keyframe, and in colour even a clean seam is noisier than its
  neighbours (0.59 against 0.40–0.49). Measured 2026-10-23, draft and final: a clean loop 1.01–1.16; a spring not settled
  by D 1.82–2.46; the last frame = frame 0 0.19. The "< 10" threshold on `loop_seam_jump` is useless for a loop (the same
  spring gives 1.1). By eye — `loop_seam.jpg` (the last 6 and first 6 frames in a row).
- **A GIF for X — up to 350 frames:** D × `--gif-fps` ≤ 350, ~14.5 s at 24 fps, 23 s at 15 fps. D × `--gif-fps` is a whole
  number, otherwise ffmpeg rounds the frame count up and the cycle grows: 5.5 s × 15 fps → 83 frames, 5.54 s. With
  `"loop": true` `share.py` checks the finished GIF with `ffprobe` (exactly D × fps frames, delays summing to D ± 0.02 s)
  and on a mismatch prints FAIL and exits 1; when it lowers the rate to fit `--mb` it skips rates with a fractional frame
  count. GIF delays are in hundredths of a second, so frames are uneven (15 fps — 7, 7, 6; 24 fps — 4 ×5, 5), but they
  sum to D.

## GIF (`share.py --gif`)
```
python3 scripts/share.py --gif [--fmt 16x9 | --all] [--width 720] [--gif-fps 15] [--mb 10] [--range 2,8]
python3 scripts/share.py --gif --src any.mp4 --out /tmp/x.gif        # any video, no timeline.json needed
```
`renders/<fmt>.gif`, silent, looping. One palette per clip (`palettegen` with `stats_mode=diff`: the colours of what moves win),
ordered dither with `diff_mode=rectangle` (each frame re-encodes only the rectangle that changed, so a still background costs
almost nothing). It starts at 720 px and 15 fps; while the file is over `--mb`, the width steps down to 320 px, then the frame

`readme-demo-16x9.mp4` (33 s, 1920x1080): the whole film is 9.1 MB at 720 px and 15 fps, 400 px to fit 4 MB; a 6 s cut is 2.0 MB
at 720 px.

## Camera, cursor, shake, focus (`lib/camera.js`, `window.CAM`)
Loaded in `index.html` after `core.js`. All functions of t; `--verify` passes.
| | |
|---|---|
| `CAM.rig(t, el, [[mark, {x, y, z}], …], {ax, ay, lead, preset, maxZoom, keep, view})` | a virtual camera over a big element (a real screenshot): focus point in its own px and zoom. Every key starts `lead` (0.4 s) before its mark: the camera arrives before the action. Zoom ≤ 3×. By default it keeps the element whole across the window (the window is a parent with `overflow: hidden`, else the frame; `view: {l, r}` sets it): a zoom whose edge would cut the screenshot is capped and the focus shifted. `keep: [x0, x1]` keeps a panel whole (a natural boundary), `keep: false` is a pan over a board wider than the frame. Call it from `run()` or `C.hooks.before` |
| `CAM.cursor(parent, [[mark, x, y, click?], …], {size, settle, hold})` | a directed cursor: an arc with ease-in and ease-out, arrives `settle` (0.12 s) before a click, a ring pulse on the click. Call it in `build()`. Returns `clicks` — marks for `click` SFX |
| `CAM.shake(t, [mark, …], {amp, decay, rot})` | trauma shake on hero hits: returns `{x, y, r, s}` for a `put()` on a scene root (s overscans so no frame edge shows) |
| `CAM.focus(t, els, hero, on)` | dims everything but the hero (opacity down to 0.35) while `on` > 0 — e.g. `C.win(t, a, b)` |
If the scene has a WebGL layer, move its 3D camera (`L.camera`) rather than scaling the scene root: otherwise the layer's raster goes soft.

## Isometry and stage themes (`lib/iso.js`, `lib/themes.js`, `scripts/fonts.sh`)
An option for the "stage and an object per phrase" style (STYLES "Stage and object"), not a default: no film turns them
on by itself.

**`ISO`** draws isometric objects on a 2D canvas. Faces are projected polygons, so a frame stays a pure function of
`seek(t)`; CSS 3D (`preserve-3d`, `perspective`) moves layers to the compositor and `--verify` fails. The x axis runs right
and slightly down, y into depth right and up, z up; an origin is `o = {cx, cy, s}`, and `ISO.centred(sx, sy, w, d, s)`
centres a w×d footprint on a screen point. Colours are `[r, g, b]` arrays.
```js
const { centred, box, shadow, stack, building, token, chip, floor } = ISO;
S.g = C.canvas(root); S.o = centred(540, 1100, 180, 104, 1.6);              // build()
g.clearRect(0, 0, W, H); shadow(g, S.o, 0, 0, 180, 104);                    // run(t): repaint everything from t
box(g, { ...S.o, x: 0, y: 0, z: 0, w: 180, d: 104, h: 19 * k, col: [118, 206, 132], edge: 'rgba(255,255,255,.3)' });
```
`box` (lit front face, shaded side, lighter top, a light rim so the thickness reads), `shadow` (a soft contact shadow),
`onFront` (draw in the plane of a front face: windows, plates), `stack` (a banded bundle), `building` (a building on a
plinth: windows, a label, chimneys, smoke on a 2.4 s loop from `t`), `token` (a billboard figure with initials), `chip`
(a label plate), `floor` (a floor with a vanishing point and crawling cross lines). The scene sets the paint order:
further back (larger y, lower z) first, or `ISO.layer` (below).

**Figures, order and labels** (2026-10-28). Volumetric objects are ready figures from `assets/figures` (LIBRARY
"Figures"): Blender renders in the same projection, tinted to the theme at runtime.
```js
useFigures(['office', 'person', 'money_stack']);                  // top of film.js: loading joins C.gates
const L = ISO.layer();                                            // run(t): paint by depth, not by call order
L.add({ x: 170, y: 110, w: 240, d: 150 }, () => figure(g, o, 'office', { x: 170, y: 110, col: [61, 90, 254], grow: k }));
L.add({ x: px, y: 20, w: 62, d: 40 }, () => figure(g, o, 'person', { x: px, y: 20, col: [255, 255, 255] }));
L.flush();
callout(g, o, px + 31, 40, 160, 'Hi!', { dx: 40, dy: -110, font: `600 34px ${T.U}`, fill: T.ink, ink: T.bg, k });
```
- `figure(g, o, name, {x, y, z, s, grow, col, accent, alpha})` — a figure at an iso point; `col` tints the body
  (multiply over the grey render), `accent` the accent details (windows, tie, screen), `grow` raises it from the floor.
- `figureQuad(g, o, name, f, paint(g, w, h), w = 300)` — paint in the plane of a figure's screen (`laptop`, `phone`,
  `portrait`): a chat, a chart, a person's photo. `paint` gets a w×h rectangle, clipped to the screen.
- `layer()` → `{add(footprint, draw), flush()}` — depth order along the camera axis. Overlaps become physically right by
  themselves; call `flush()` after every `add`.
- `onTop(g, o, x, y, z)` — sets the transform to the plane of a top face (origin at its far-left corner); text reads
  upright. Restore with `g.setTransform(1, 0, 0, 1, 0, 0)` afterwards. The projection has a negative determinant, so
  text on a top face comes out mirrored without `onTop`.
- `callout(g, o, x, y, z, text, {dx, dy, font, fill, ink, pad, k})` — a bubble plate with a tail to a point on the object.
- `note(text)` — register painted text for `--lint` (`window.CANVAS_TEXT`, cleared every frame). `chip` and `callout`
  call it themselves; call it by hand after your own `fillText` on a canvas.

**`THEMES`** holds seven ready themes: palette, light on the stage, fonts, object colours. `reference` is what everyone does
(purple-orange haze, wide grotesque caps), kept for comparison; the other six replace it:

|---|---|---|---|

otherwise fetched only its Latin file, and Cyrillic vanished from the first frames (found 2026-10-28 on `blueprint`).
