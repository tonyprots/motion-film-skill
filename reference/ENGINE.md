## timeline.json
```jsonc
{
  "duration": 16, "fps": 60, "bpm": 120, "formats": ["16x9", "9x16"],   // 16x9 1x1 4x5 9x16
  "marks": { "hook": 0, "hook_w2": 1, "mid": 8, "end": 24, "done": 32 },  // beats; half-beats allowed
  "sfx": [ { "at": "hook_w2", "type": "pop", "gain": 0.6, "what": "word 2" },
           { "at": 16, "to": 18, "every": 0.25, "type": "tick", "gain": 0.35, "what": "typing" } ],
  "music": { "source": "synth", "chords": ["Am","F","C","G"], "sections": [{ "at": "hook", "kind": "intro" }], "accents": ["end"] },
  "mix": { "music": 0, "sfx": -3, "vo": 0, "duck": true },
  "voiceover": null
}
```
Change it, then run `node scripts/sync.mjs`. The film and the SFX both read it, so picture and sound cannot drift.

## core.js API (`window.C`)
| | |
|---|---|
| `C.W, C.H, C.FMT, C.FPS, C.DUR` | frame size from `?fmt=`; `C.pick(wide, square, tall)` returns a per-format value |
| `C.bt(beatOrMark)` / `C.beatAt(t)` | beat ↔ seconds on the measured grid |
| `C.sp(t, beat, preset)` | 0→1 spring released on a beat (motion with no sound) |
| `C.spHit(t, beat, preset)` | same, but led so it READS on the beat (anything with an SFX or VO hit) |
| `C.trk(t, [[beat, v, preset?], …])` / `C.trkObj` | value with several targets. Retargets keep velocity |
| `C.win(t, b0, b1)` | 1 inside [b0, b1) with spring edges |
| `C.seg(t, b0, b1)` + `C.ease.*` | linear progress. Only for typing, scrolls, slow pushes, push-throughs |
| `Motion.indicator(t, stops)` | bar/underline between stops: the leading edge is stiffer, so it stretches and settles |
| `Motion.swapAlpha(t, tIn, tOut)` | text inside a morphing box. Invisible while the box changes shape |
| `C.el(tag, attrs, parent, html)` `C.frag(html)` | build DOM (in `build()` only) |
| `C.reg(el, base)` | register an animated element. Hidden things: `{o: 0}` |
| `C.put(el, {x, y, s, sx, sy, r, o, hide, clip, filter, css, text, html})` | this frame's props; unset props return to base |
| `C.inset(t, r, b, l, radius)` | clip-path for wipes/reveals |
| `C.rectOf(el)` | live stage rect. Only in `after()` |
| `C.canvas(parent)` | full-frame 2D context (clear it in `run()` every frame) |
| `C.hooks.before/after.push(fn)` | global per-frame work: camera, cursor, overlays |
| `C.mulberry32(seed)`, `C.noise1(seed)` | seeded randomness |
| `C.fonts = ['600 100px Display', …]` | awaited before frame 0. A missing face logs `[page] font failed` |

## Scenes
```js
scene({
  name: 'features', from: 'mid', to: 'end',   // beats or marks; root visible on [from - pre, to + post)
  pre: 0, post: 0,                              // overlap for whips/wipes. cut defaults to pre === 0
  build(root, S) { /* DOM once; store on S */ },
  run(t, b, S)   { /* put() everything you animate, every frame */ },
  after(t, b, S) { /* things that follow live layout (rectOf) */ },
});
C.start();   // last line of film.js
```
`window.CUTS` is derived from scenes with `cut`. Motion-blur sub-frames never straddle a cut.

## Type (`window.TYPE`)

```js
S.h = TYPE.line(root, 'Ship it today.', { x: 140, y: 380, size: C.pick(220, 170, 120), accent: [2] });
TYPE.rise(t, S.h, ['w1', 'w2', 'w3'], 'next_in', { preset: 'heavy', exit: 0.28 });  // per-word hits, sequential exit

```

## Patterns that fixed real problems
- **Hook on frame 0:** release word 0 at a negative beat (`[-0.4, …]`) so frame 0 already reads.
- **Sync:** visuals read ~100 ms late when a masked word starts on the beat. `spHit` leads by max(3 frames, half the spring's travel).
- **Swaps:** set `outAt` from the next line's in-beat. Exit ≈ 0.14 s. No double exposure at swaps.
- **Handoffs:** start the incoming scene under full cover (a wipe or whip) so there are no blank frames mid-whip.
- **9:16:** re-block per format with `pick()`. Don't letterbox 16:9. Move things apart vertically and use bigger crops of the real UI.
- **Loop:** if the reel loops, close on the frame it opens on (black → black, or the same background) and end the audio on a swell into the loop point.
- **Camera multipliers compound.** If one scene multiplies zoom, divide it out downstream.
- **Depth:** perspective on UI cards settling from 12–22° toward ~3°, plus deep soft contact shadows. Never glow. CSS 3D creates composited layers: run `render.mjs --verify`, and fall back to 2D skew + scale if it fails.

## Render speed (motion-film)
Video modes (`--draft`, finals, `--range`) run in parallel: the range is cut into `--chunk` seconds (default 4) and
`--workers` processes (default: CPU cores − 4, max 4), each with its own Chromium, encode chunks that are joined
losslessly. Measured on an Apple M1 (8 cores), 2:36 film, 1920×1080, 60 fps with motion blur: **9 min 46 s instead of
~42 min**. Two changes do it:
- `png.mjs` decodes Chromium's screenshots with typed-array fast paths: 4–10 ms instead of ~40 ms per frame,
  bit-exact (the single-process output is byte-identical to the original renderer);
- parallel chunks: ×2.4 on top. More than 4 workers is slower on an M1 (4 performance cores).
Parallel and serial output differ only where Chromium's raster cache depends on which frame it painted before (edge
antialiasing of a moving card): worst frame 71 dB PSNR against a serial render, sharpness equal. `--workers 1` gives
the serial path. GPU flags (`--use-angle=metal`) make screenshots 5× slower: do not add them.
